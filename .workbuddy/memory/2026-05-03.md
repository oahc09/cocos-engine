## Blend State 开关排查 (下午)
- **结论: blend 开关无问题**
- D3D12 的 blend state 是**静态编译进 PSO** 的（与 WebGL 动态开关不同）
- `SetPipelineState()` 调用会原子性切换整个管线状态，不存在"上一个 PSO 的 blend 开关残留到下一个 PSO"的问题
- 数据流验证: `BlendTarget.blend` (uint32_t) → `target.blend ? TRUE : FALSE` → `rtBlend.BlendEnable`，转换正确
- JSB 层: TS `BlendTarget.blend` (boolean) → `_nativeObj.blend` (uint32_t 0/1)，传递正确
- `makeDefaultRenderTargetBlendDesc()` 确保 8 个 RTV 槽位都有正确默认值 (BlendEnable=FALSE)
- 与 WebGL 对比: WebGL 需要手动 `gl.enable(gl.BLEND)`/`gl.disable(gl.BLEND)`，D3D12 不需要

## 修复 Present 不被调用的根因 (晚上)
- **根因**: `CCD3D12Device::present()` 调用 `getSwapchains()` 返回空数组 → Present 永远不执行
- **原因**: 引擎的 Device 层是三层包装: `DeviceAgent → DeviceValidator → CCD3D12Device`
  - `Device::createSwapchain(info)` (非虚) 在最外层 DeviceAgent 上执行 `_swapchains.push_back`
  - 内层 `CCD3D12Device` 的 `_swapchains` 从未被填充（private 也无法访问）
  - `present()` 在内层调用 `getSwapchains()` 拿到空列表
- **修复方案**: 在 `acquire()` 中从传入参数收集 swapchain 指针
  - DeviceAgent::acquire() 会 unwrap SwapchainAgent → SwapchainValidator
  - DeviceValidator::acquire() 会 unwrap SwapchainValidator → CCD3D12Swapchain
  - 所以 CCD3D12Device::acquire() 收到的已经是裸 CCD3D12Swapchain*
  - 存入 `_d3d12Swapchains` 成员，`present()` 遍历它调用 Present()
- **文件**: D3D12Device.h (新增 _d3d12Swapchains), D3D12Device.cpp (acquire/present)
