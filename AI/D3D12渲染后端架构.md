# D3D12 渲染后端架构文档

## 1. 概述

D3D12 渲染后端是 Cocos Creator 引擎 GFX（Graphics Framework）抽象层的 DirectX 12 实现。它位于 `native/cocos/renderer/gfx-d3d12/` 目录下，由 16 个类（15 个继承自 gfx-base 抽象类 + 1 个工具类）组成，负责将引擎的 GPU 无关渲染 API 翻译为 D3D12 原生调用。

### 三层架构

```
┌─────────────────────────────────────────────┐
│           Engine / Game Thread              │
├─────────────────────────────────────────────┤
│  DeviceValidator (参数校验 / 调试拦截)       │
├─────────────────────────────────────────────┤
│  DeviceAgent (多线程命令队列，可选)           │
│    MessageQueue → 延迟执行 / 立即执行         │
├─────────────────────────────────────────────┤
│  CCD3D12Device (D3D12 后端，本目录)          │
│    直接操作 ID3D12Device / DXGI              │
├─────────────────────────────────────────────┤
│  D3D12 Runtime / GPU Driver                 │
└─────────────────────────────────────────────┘
```

- **DeviceValidator**：参数校验层，对所有 GFX 调用做边界检查和类型验证
- **DeviceAgent**：多线程代理层，通过 MessageQueue 将游戏线程的渲染命令延迟转发到渲染线程（单线程模式下直接透传）
- **CCD3D12Device**：D3D12 后端实现，完全不感知上层线程模型

## 4. 核心设计模式

### 4.1 Pimpl 惯用法

所有类均使用 `struct Impl; std::unique_ptr<Impl> _impl` 隐藏 D3D12 COM 类型的实现细节。公共头文件仅暴露 `void*` 句柄或简单的 POD 返回值，避免了在头文件中包含 `<d3d12.h>`（仅 `D3D12Texture.h` 因 `D3D12_RESOURCE_STATES` 状态追踪而例外）。

### 4.2 模板方法模式（doInit / doDestroy）

gfx-base 基类定义了非虚的 `initialize(Info)` / `destroy()` 公共方法，内部完成对象注册和状态管理后，调用纯虚的 `doInit()` / `doDestroy()`。D3D12 子类仅重写 `doXxx` 方法。

### 4.3 单例设备工厂

`CCD3D12Device` 是单例（`getInstance()`），拥有所有 GPU 上下文并充当所有 GFX 对象的工厂。每个 `createXxx()` 返回对应的 `new CCD3D12Xxx` 实例。

## 5. 各模块详解

### 5.1 CCD3D12Device — 设备与 GPU 上下文

**核心职责：** D3D12 设备初始化、GPU 对象工厂、帧同步、呈现。

**持有的 D3D12 资源：**
- `IDXGIFactory6` — DXGI 工厂
- `ID3D12Device` — D3D12 设备
- `ID3D12CommandQueue` — 图形命令队列
- `ID3D12CommandAllocator` — 命令分配器
- `ID3D12GraphicsCommandList` — 图形命令列表
- `ID3D12Fence` — CPU/GPU 同步围栏
- 2 个 `D3D12DescriptorHeapPool`（CBV/SRV/UAV + Sampler，GPU 可见）
- Dummy 资源（`CCD3D12Texture`、`CCD3D12Buffer`）用于空绑定的安全回退
- Indirect Draw/Dispatch 的 Command Signature

**帧生命周期：**
```
acquire(swapchains) → 录制命令 → Queue::submit → present()
```

**关键方法：**
| 方法 | 说明 |
|------|------|
| `doInit(DeviceInfo)` | 创建 D3D12 设备、命令队列、命令分配器/列表、Fence、描述符堆池、Dummy 资源 |
| `acquire()` | 重置描述符堆池、开始命令录制 |
| `present()` | 执行命令列表、Present、等待 GPU 完成 |
| `waitForGpu()` | Signal Fence + 等待（5 秒超时） |

### 5.2 CCD3D12CommandBuffer — 命令录制

**核心职责：** 将所有渲染命令录制到 `ID3D12GraphicsCommandList`。这是最大的类（~1675 行实现）。

**命令分类：**

| 类别 | 方法 |
|------|------|
| 生命周期 | `begin()`, `end()` |
| 渲染通道 | `beginRenderPass()`, `endRenderPass()`, `nextSubpass()` |
| 状态绑定 | `bindPipelineState()`, `bindDescriptorSet()`, `bindInputAssembler()` |
| 动态状态 | `setViewport()`, `setScissor()`, `setDepthBias()`, `setBlendConstants()`, `setStencilWriteMask()`, `setStencilCompareMask()` |
| 绘制/分发 | `draw()`, `dispatch()` |
| 拷贝操作 | `updateBuffer()`, `copyBuffersToTexture()`, `blitTexture()`, `copyTexture()`, `resolveTexture()` |
| 同步 | `pipelineBarrier()` |
| 查询 | `beginQuery()`, `endQuery()`, `resetQueryPool()` |
| 调试 | `insertMarker()`, `beginMarker()`, `endMarker()` |

**描述符刷新机制（`flushDescriptorSets()`）：**
在每次 draw/dispatch 调用前自动触发，将所有待绑定的 DescriptorSet 的 CPU 描述符拷贝到 GPU 可见描述符堆：
1. 从 Device 的 `D3D12DescriptorHeapPool` 分配连续描述符块
2. `CopyDescriptorsSimple` 从各 DescriptorSet 的 CPU 暂存堆拷贝到 GPU 堆
3. `SetDescriptorHeaps` + `SetGraphicsRootDescriptorTable` 绑定到命令列表

**RenderPass 资源转换：**
- `beginRenderPass`：交换链缓冲 PRESENT → RENDER_TARGET，颜色纹理 → RENDER_TARGET，深度 → DEPTH_WRITE
- `endRenderPass`：反向转换回 PRESENT / PIXEL_SHADER_RESOURCE / DEPTH_READ

### 5.3 CCD3D12Swapchain — 交换链

**核心职责：** DXGI 交换链管理、后缓冲创建、RTV 创建、Present。

- 使用 `IDXGISwapChain3` 管理后缓冲
- 后缓冲被包装为 `CCD3D12Texture` 对象（标记为 `isSwapchainColorTexture()`）
- `getCurrentRTVHandle()` 返回当前帧的渲染目标视图

### 5.4 CCD3D12Queue — 命令队列

**核心职责：** 命令提交 + Fence 同步。

- `submit()` 关闭命令列表、执行 `ExecuteCommandLists`、Signal Fence、同步等待（5 秒超时）
- 当前实现为同步模式

### 5.5 CCD3D12Buffer — GPU 缓冲区

**核心职责：** 管理 D3D12 缓冲区资源（`ID3D12Resource`，UPLOAD 堆）。

- 支持 `update()` 通过 Map/Unmap 更新数据
- 暴露 GPU 虚拟地址（`getD3D12GPUVirtualAddress()`）用于 CBV 创建
- 支持 `BufferView`（`doInit(BufferViewInfo)`）

### 5.6 CCD3D12Texture — GPU 纹理

**核心职责：** 管理 D3D12 纹理资源（`ID3D12Resource`，DEFAULT 堆）+ 资源状态追踪。

- 内置 `D3D12_RESOURCE_STATES _currentState` 用于 `pipelineBarrier` 的状态转换
- 支持三种初始化模式：直接纹理、纹理视图、交换链纹理
- 交换链颜色纹理的 `getD3D12ResourceHandle()` 动态返回当前后缓冲
- 支持 `doResize()` 用于窗口大小变化时重建资源

### 5.7 CCD3D12Shader — 着色器编译

**核心职责：** 三阶段着色器编译管线。

```
GLSL 450 ──(glslang)──→ SPIR-V 1.3 ──(SPIRV-Cross)──→ HLSL SM5.1 ──(D3DCompile)──→ DXBC
```

**入口点发现策略：** 依次尝试 `main`、`vert_main`/`frag_main`（SPIRV-Cross 约定）、正则检测函数名。

**多阶段支持：** VS / FS / GS / CS / HS / DS 各阶段独立编译并缓存字节码。

### 5.8 CCD3D12PipelineState — 管线状态对象

**核心职责：** 创建 `ID3D12PipelineState`。

**PSO 包含的完整图形状态：**
- 着色器字节码（VS/FS/GS/HS/DS）
- Blend State（混合状态）
- Rasterizer State（光栅化状态）
- Depth-Stencil State（深度模板状态）
- Input Layout（输入布局）
- Primitive Topology Type（图元拓扑类型）
- Render Pass 格式信息（RTV formats, DSV format, sample count）
- Root Signature（根签名）

### 5.9 CCD3D12PipelineLayout — 根签名

**核心职责：** 将引擎的 DescriptorSetLayout 绑定映射为 D3D12 Root Signature。

**映射规则：**
- 每个 Descriptor Set 生成最多 2 个 Root Parameter：一个 CBV/SRV/UAV 描述符表 + 一个 Sampler 描述符表
- Register Space = Descriptor Set Index（set 0 → space 0），匹配 SPIRV-Cross 的 HLSL 输出
- 提供 `getCbvSrvUavRootParameterIndex(set)` 和 `getSamplerRootParameterIndex(set)` 查询 Root Parameter 索引

### 5.10 CCD3D12DescriptorSet — 描述符集

**核心职责：** CPU 侧描述符暂存 + 绑定管理。

**两阶段描述符管理：**

```
阶段 1 — CPU 暂存（本类）：
  forceUpdate() → 将 CBV/SRV/UAV/Sampler 写入 CPU 可见描述符堆
  空绑定 → 使用 Dummy 资源描述符（防止 GPU 崩溃）

阶段 2 — GPU 拷贝（CommandBuffer::flushDescriptorSets）：
  从 Device 的 DescriptorHeapPool 分配 GPU 可见空间
  CopyDescriptorsSimple → 批量拷贝到 GPU 堆
  SetDescriptorHeaps + SetRootDescriptorTable → 绑定到管线
```

### 5.11 CCD3D12DescriptorSetLayout — 描述符集布局

**核心职责：** 按类型统计描述符数量（Sampler / Texture / Buffer / StorageImage / InputAttachment）。

- 不创建 D3D12 对象，仅存储绑定元数据
- 用于 `PipelineLayout` 构建 Root Signature 和 `DescriptorSet` 分配描述符

### 5.12 D3D12DescriptorHeapPool — 描述符堆池（工具类）

**核心职责：** 管理每帧分配/回收的 GPU 可见描述符堆。

**设计特点：**
- 支持 CBV_SRV_UAV 和 SAMPLER 两种堆类型
- `allocate(count)` 返回连续描述符块（含 CPU/GPU 句柄）
- `reset()` 每帧调用，回收所有分配
- 可配置每堆最大描述符数（默认 1024）
- 独立于 gfx-base 层，由 Device 直接持有

### 5.13 CCD3D12Framebuffer — 帧缓冲

**核心职责：** 创建和管理 RTV（渲染目标视图）+ DSV（深度模板视图）描述符堆。

- 检测交换链纹理并路由 RTV 句柄
- 暴露 `getRTVHandle(index)` 和 `getDSVHandle()` 供 CommandBuffer 使用

### 5.14 CCD3D12RenderPass — 渲染通道

**核心职责：** 存储颜色和深度附件的 DXGI 格式信息。

- 不创建 D3D12 对象，仅存储格式元数据
- `getRTVFormats()`、`getDSVFormat()` 供 PSO 创建时使用

### 5.15 CCD3D12InputAssembler — 输入装配

**核心职责：** 顶点输入布局 + 顶点/索引缓冲视图。

- `D3D12_INPUT_ELEMENT_DESC[]` 描述顶点属性布局
- `fillVertexBufferViews()` / `fillIndexBufferView()` 填充 D3D12 视图结构

### 5.16 CCD3D12QueryPool — 查询池

**核心职责：** 遮挡查询和时间戳查询。

- 使用 `ID3D12QueryHeap` + Readback Buffer
- `fetchResults()` 将 GPU 查询结果读回 CPU

## 6. 数据流：一帧的渲染流程

```
1. CCD3D12Device::acquire()
   ├── 重置 GPU 描述符堆池（per-frame reset）
   ├── 重置命令分配器
   └── 开始命令录制

2. CCD3D12CommandBuffer 录制
   ├── beginRenderPass → 资源状态转换（PRESENT → RENDER_TARGET）
   ├── bindPipelineState → 设置 PSO + Root Signature
   ├── bindDescriptorSet → 记录待绑定描述符集
   │     └── flushDescriptorSets() → CPU 描述符拷贝到 GPU 堆 → 绑定
   ├── bindInputAssembler → 设置顶点/索引缓冲
   ├── draw / dispatch → GPU 工作
   └── endRenderPass → 资源状态转换（RENDER_TARGET → PRESENT）

3. CCD3D12Queue::submit()
   ├── 关闭命令列表
   ├── ExecuteCommandLists
   └── Signal Fence + 等待

4. CCD3D12Device::present()
   ├── ExecuteCommandLists（如果有残留命令）
   ├── IDXGISwapChain::Present()
   └── waitForGpu()
```

## 8. 关键子系统

### 8.1 描述符管理系统

这是 D3D12 后端最复杂的子系统。D3D12 要求 GPU 可见的描述符堆才能在着色器中访问资源，但每个命令列表同时只能绑定一个 CBV/SRV/UAV 堆和一个 Sampler 堆。

```
┌─────────────────────────────────────────────────────┐
│                  DescriptorSet (CPU 暂存)            │
│  ┌─────────────┐  ┌─────────────┐                    │
│  │ CBV/SRV/UAV │  │   Sampler   │                    │
│  │  CPU Heap   │  │  CPU Heap   │                    │
│  └──────┬──────┘  └──────┬──────┘                    │
│         │                │                           │
│  forceUpdate() 写入描述符                            │
│  空绑定 → Dummy 资源描述符                            │
└─────────┼────────────────┼───────────────────────────┘
          │ CopyDescriptorsSimple
          ▼                ▼
┌─────────────────────────────────────────────────────┐
│          D3D12DescriptorHeapPool (GPU 可见)          │
│  ┌─────────────────────────────────────────────────┐│
│  │ CBV/SRV/UAV Heap (Shader Visible)               ││
│  └─────────────────────────────────────────────────┘│
│  ┌─────────────────────────────────────────────────┐│
│  │ Sampler Heap (Shader Visible)                    ││
│  └─────────────────────────────────────────────────┘│
│  每帧 reset() 回收 → allocate() 分配                 │
└─────────────────────────────────────────────────────┘
          │
          │ SetDescriptorHeaps + SetRootDescriptorTable
          ▼
┌─────────────────────────────────────────────────────┐
│          ID3D12GraphicsCommandList                   │
└─────────────────────────────────────────────────────┘
```

### 8.2 着色器编译管线

```
引擎 GLSL 4.x 源码
       │
       ▼  glslang (GLSL → SPIR-V)
  SPIR-V 1.3 中间码
       │
       ▼  SPIRV-Cross (SPIR-V → HLSL)
  HLSL SM 5.1 + 显式绑定
  (register space = descriptor set index)
       │
       ▼  D3DCompile (HLSL → DXBC)
  DXBC 字节码
  (per-stage: VS/FS/GS/CS/HS/DS)
```

### 8.3 Root Signature 映射

```
引擎 PipelineLayout
  ├── DescriptorSetLayout[0]
  │     ├── Sampler bindings    → Root Param 0: Sampler Descriptor Table (space 0)
  │     └── CBV/SRV/UAV bindings → Root Param 1: CBV/SRV/UAV Descriptor Table (space 0)
  ├── DescriptorSetLayout[1]
  │     ├── Sampler bindings    → Root Param 2: Sampler Descriptor Table (space 1)
  │     └── CBV/SRV/UAV bindings → Root Param 3: CBV/SRV/UAV Descriptor Table (space 1)
  └── ...
```

### 8.4 资源状态追踪

`CCD3D12Texture` 内置 `D3D12_RESOURCE_STATES _currentState`，由 `CCD3D12CommandBuffer` 管理：

| 时机 | 转换 |
|------|------|
| beginRenderPass | PRESENT → RENDER_TARGET（交换链）、* → RENDER_TARGET（颜色）、* → DEPTH_WRITE（深度） |
| endRenderPass | RENDER_TARGET → PRESENT（交换链）、RENDER_TARGET → PIXEL_SHADER_RESOURCE、DEPTH_WRITE → DEPTH_READ |
| pipelineBarrier | 引擎 `AccessFlags` → D3D12_RESOURCE_STATES 映射 + `ResourceBarrier` 调用 |

## 9. 多线程渲染与 Agent 层

D3D12 后端本身不感知多线程。多线程渲染由上层的 Agent 层（`gfx-agent/`）实现：

```
DeviceValidator → DeviceAgent → CCD3D12Device
```

**Agent 层机制：**
- `Agent<T>` 模板继承自 `T`，持有真实后端对象的指针 `_actor`
- 所有方法调用通过 `ENQUEUE_MESSAGE` 宏记录到 `MessageQueue`
- 多线程模式：游戏线程录制 → 渲染线程回放
- 单线程模式：立即执行，透传到后端
- CPU/GPU 流水线：`MAX_CPU_FRAME_AHEAD = 1`，游戏线程最多领先渲染线程 1 帧
- 指针翻译：Agent 对象在游戏线程，Actor 对象在渲染线程，`getActor()` 在入队时完成翻译

**D3D12 后端完全不需要关心这些**——它只接收同步的方法调用，就像单线程模式一样工作。
