## 2) 模块边界说明（TS层 / Native层 / PAL / Platform）

### TS层（`cocos/` + `exports/`）
- 负责引擎主体逻辑与模块组织；用户 API 通过 `exports/` 暴露。
- `docs/contribution/modules.md` 定义了“可见性边界”：**仅公共模块导出可见**。
- `cc` 是聚合入口，汇总用户选择的公共模块。

### Native层（`native/cocos/`）
- 负责原生运行时底层实现（渲染、资源、平台交互、系统接口等）。
- 与 TS 层通过 `cocos/native-binding/` + JSB 进行桥接。

### PAL层（`pal/`）
- 位于 TS 域内的“平台抽象层”，统一音频、输入、系统信息、屏幕适配、环境、wasm 等接口。
- 通过 `moduleOverrides` 将 `pal/*` 映射到 web/native/minigame 的具体实现。
- `checkPalIntegrity()` 用于约束“接口/实现”一致性，降低平台分叉风险。

### Platform层（Native Platform + 构建适配 Platform）
- **原生平台抽象**：`native/cocos/platform/`，含 `BasePlatform` 与各 OS 子实现，处理 init/run/loop/poll/exit 等生命周期。
- **构建适配层**：`platforms/`，按 `native/minigame/runtime` 提供目标平台适配与发布脚本。

### 边界关系（一句话）
- 用户与业务代码通过 `cc`/公共模块进入 TS 引擎层；TS 层借助 PAL 抽象平台差异，并在需要时通过 Native Binding 进入 Native 层；Native 层再落到具体 Platform 实现。
