# 阶段2-场景与资源主链路（S2-T2）

> 范围：`cocos/scene-graph/` + `cocos/asset/`  
> 目标：看清“场景对象 -> 场景资源加载 -> 场景切换 -> 资源引用释放”的完整链路。

---

## 1. 关键结论（先看）

- 场景实体是 `Scene`（继承 `Node`），定义在 `cocos/scene-graph/scene.ts`。
- 场景资源是 `SceneAsset`（继承 `Asset`），定义在 `cocos/asset/assets/scene-asset.ts`。
- 场景加载入口在 `Bundle.loadScene()` 与 `Director.loadScene()`。
- 资源加载总入口是 `AssetManager.loadAny()`，预加载入口是 `AssetManager.preloadAny()`。
- 场景切换后资源释放由 `releaseManager._autoRelease(...)` 驱动，结合 `Asset.refCount` 计数决策。

---

## 2. scene-graph 主链路（对象层）

## 2.1 `Node` 与 `Scene` 的关系

- `Scene` 继承 `Node`，本质是场景树根节点。
- `Node` 负责：层级、组件、激活状态（`active` / `activeInHierarchy`）、场景归属（`scene`）。
- `Scene` 额外负责：
  - 渲染场景对象 `renderScene`
  - 场景级开关 `autoReleaseAssets`
  - 生命周期入口 `_load()`、`_activate()`

## 2.2 场景激活路径

- `Scene._load()`：
  - 处理 prefab 展开与目标覆盖
  - 批量创建回调
  - `walk(Node._setScene)` 把节点挂接到当前场景
- `Scene._activate(active)`：
  - 通过 `director._nodeActivator.activateNode(...)` 激活节点树
  - 激活场景级全局渲染配置（`_globals.activate(this)`）

---

## 3. asset 主链路（资源层）

## 3.1 角色分工

- `Asset`：基础资源类，包含 `_uuid`、`refCount`、`addRef()/decRef()`。
- `SceneAsset`：场景资源封装，核心字段 `scene: Scene | null`。
- `AssetManager`：统一加载/预加载/释放调度中心。
- `Bundle`：按包组织资源与场景（`load`/`loadDir`/`loadScene`/`release`）。
- `ReleaseManager`：按引用与依赖图执行释放。

## 3.2 加载管线

- `AssetManager.loadAny(...)`
  - 默认 `preset='default'`
  - 构建 `Task` 并交给 `pipeline.async(task)`
  - 是所有高阶 API（如 `Bundle.load`/`Bundle.loadScene`）最终落点

- `AssetManager.preloadAny(...)`
  - 默认 `preset='preload'`
  - 走 `fetchPipeline.async(task)`，只下载不完整解析

- `Bundle.loadScene(sceneName, ...)`
  - 设置 `opts.preset='scene'`、`opts.bundle=this.name`
  - 调用 `assetManager.loadAny({ scene: sceneName }, ...)`
  - 成功后把 `sceneAsset.scene` 的 `id/name` 对齐到资源信息

---

## 4. 场景与资源联动链路（从调用到落地）

## 链路A：场景加载

1. `director.loadScene(sceneName)` 找到包含场景的 bundle。  
2. `bundle.loadScene(sceneName)` -> `assetManager.loadAny({scene})`。  
3. 得到 `SceneAsset`，取出 `Scene` 实例。  
4. `director.runSceneImmediate(scene)`：
   - `scene._load()`
   - 常驻节点重挂接
   - 旧场景销毁 + 资源 auto release
   - `scene._activate()`

## 链路B：资源引用与释放

1. 资源加载后进入 `assets` 缓存。  
2. 业务层可用 `asset.addRef()` 保活。  
3. 调用 `asset.decRef()` 时，`ReleaseManager.tryRelease(asset)` 进入释放候选。  
4. 场景切换时 `releaseManager._autoRelease(oldScene, newScene, persistNodes)`：
   - 旧场景依赖 `decRef`  
   - 常驻节点依赖转移到新场景  
5. 引用计数归零且依赖可清理时执行真正释放。

---

## 5. 高价值接口速查

- 场景对象：`Scene._load()` / `Scene._activate()`
- 场景调度：`Director.loadScene()` / `Director.runSceneImmediate()`
- 统一加载：`AssetManager.loadAny()` / `AssetManager.preloadAny()`
- Bundle层：`Bundle.load()` / `Bundle.loadDir()` / `Bundle.loadScene()`
- 释放控制：`Asset.addRef()` / `Asset.decRef()` / `AssetManager.releaseAsset()` / `ReleaseManager._autoRelease()`

---

## 6. 常见问题与排查顺序

1. **场景名加载失败**：先看 `director.loadScene` 是否找到 bundle 的 `getSceneInfo(sceneName)`。  
2. **场景切换后资源黑屏**：排查是否提前 `releaseAsset` 或引用计数被提前清零。  
3. **预加载后仍卡顿**：确认是否仅调用了 `preloadAny`，未调用 `loadAny` 完成解析。  
4. **切场后内存不降**：检查常驻节点是否持有资源引用（`_persistNode` 路径）。
