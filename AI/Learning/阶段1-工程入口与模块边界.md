## 2. 顶层目录职责图（工程视角）

## 2.1 分层职责

| 层级 | 关键目录 | 核心职责 |
| --- | --- | --- |
| 运行时逻辑层 | `cocos/` | TS 引擎核心实现（core、scene、asset、render、physics、ui） |
| 原生实现层 | `native/cocos/` | C++ 原生后端（renderer、platform、bindings、core） |
| 平台抽象层 | `pal/` | 统一平台接口（system-info、input、audio 等） |
| API 导出层 | `exports/` | 公共模块导出与 `cc` 聚合入口 |
| 平台适配层 | `platforms/` | native/minigame/runtime 的适配脚本与入口 |
| 构建与工具层 | `scripts/`、`native/cmake/` | JS 构建脚本、native CMake 入口与预定义 |
| 配置治理层 | `cc.config.json`、`tsconfig.json` | feature 组合、module override、TS 编译与类型边界 |
| 验证与文档层 | `tests/`、`docs/`、`AI/Learning/` | 测试、贡献规范、学习资产沉淀 |

## 2.2 目录职责关系图（文字版）

- 用户代码通过 `exports/`/`cc` 进入 `cocos/`。
- `cocos/` 在平台相关能力上依赖 `pal/` 抽象。
- 涉及原生能力时通过 `cocos/native-binding` 进入 `native/cocos/bindings`，再下沉到 `native/cocos/` 各模块。
- 构建链由 `package.json` 脚本入口驱动，`cc.config.json` 与 `tsconfig.json` 控制编译行为与模块选择。

## 3. 构建入口图（命令与配置双视角）

## 3.1 JS/TS 构建入口

| 入口 | 类型 | 作用 | 关键关联 |
| --- | --- | --- | --- |
| `package.json` -> `build:dev` | 命令 | 开发态构建（含 debug info） | `scripts/build-h5-source.js` |
| `package.json` -> `build:min` | 命令 | 发布态压缩构建 | `scripts/build-h5-minified.js` |
| `package.json` -> `build:declaration` | 命令 | 生成声明并刷新常量 | `scripts/build-declarations.js`、`build-const.js` |
| `package.json` -> `build:adapter` | 命令 | 构建适配器产物 | `scripts/build-adapter.js`、`platforms/` |
| `package.json` -> `test` | 命令 | TS 类型 + 单测门禁 | `tsc --noEmit`、`jest` |

## 3.2 Native 构建入口

| 入口 | 类型 | 作用 | 关键关联 |
| --- | --- | --- | --- |
| `native/CMakeLists.txt` | 构建入口 | Native C++ 总构建入口 | `native/cocos/renderer`、`native/cocos/platform` 等 |
| `native/cmake/predefine.cmake` | 构建配置 | Native 预定义与开关 | 平台参数、后端裁剪 |
| `native/package.json` -> `clear-platform` | 清理命令 | 平台三方依赖清理 | `native/utils/clear-platform.js` |

## 3.3 构建入口图（流程）

1. 依赖与初始化：`npm install`（触发 `postinstall`）
2. JS 构建主分支：`build:dev`（调试）或 `build:min`（发布）
3. 配置控制分支：
   - `tsconfig.json` 控制类型与编译边界
   - `cc.config.json` 控制 feature、常量、override 与裁剪
4. Native 分支：CMake 配置 + CMake 编译（必要时先 `clear-platform`）
