> 范围：`animation` / `ui` / `physics` / `audio`  
> 目标：补齐四类常用功能模块的“入口文件、核心类、运行时挂点、边界与排障路径”。

---

## 1. 四模块定位总览（速查）

| 模块 | 目录入口 | 核心类/系统 | 运行时挂点 | 典型边界 |
| --- | --- | --- | --- | --- |
| Animation | `cocos/animation/index.ts` | `Animation`、`AnimationState`、`AnimationManager` | `AnimationManager` 在 `DirectorEvent.INIT` 注册系统 | 动画调度在 `cocos/animation`，骨骼扩展在 `cocos/3d/skeletal-animation` |
| UI | `cocos/ui/index.ts` + `cocos/2d/framework/index.ts` | `Canvas`、`UITransform`、`Widget`、`Batcher2D` | 每帧由 `Root.frameMove()` 驱动 `batcher2D.update()` | 通用 UI 组件在 `cocos/ui`，2D 渲染基础在 `cocos/2d` |

## 2. Animation 模块

## 2.1 入口与核心对象

- 入口导出：`cocos/animation/index.ts`
- 关键对象：
  - `Animation`（组件层，`cocos/animation/animation-component.ts`）
  - `AnimationState`（状态层）
  - `AnimationManager`（系统层，`cocos/animation/animation-manager.ts`）

## 2.2 运行时链路

1. `Animation` 持有 `clips` / `defaultClip` 并在 `onLoad()` 初始化状态。  
2. `Animation.play()/crossFade()` 触发状态切换。  
3. `AnimationManager.update(dt)` 统一推进 crossFade、state 更新与延迟事件。  
4. `AnimationManager` 在 `DirectorEvent.INIT` 注册到 `director`（`SystemPriority.HIGH`）。

## 2.3 模块边界

- 通用动画主流程在 `cocos/animation`。
- 骨骼动画能力（如 `SkeletalAnimation`）在 `cocos/3d/skeletal-animation`，是 animation 的扩展协作层。

---

## 3. UI 模块

## 3.1 入口与核心对象

- 组件入口：`cocos/ui/index.ts`（`Button`、`ScrollView`、`Widget` 等）
- 2D UI 基础：`cocos/2d/framework/index.ts`
- 关键对象：
  - `Canvas`（UI 根与屏幕对齐）
  - `UITransform`（尺寸、锚点、UI 空间变换）
  - `Batcher2D`（UI 批处理渲染）

## 3.2 运行时链路

1. 场景中的 UI 通常从 `Canvas` 作为根进入。  
2. `UITransform` 负责节点 UI 尺寸/锚点变化并触发渲染脏标记。  
3. `Batcher2D` 维护 screen 列表、批次和相机可见性。  
4. 每帧在渲染阶段由 `Root.frameMove()` 调用 `batcher2D.update()`。

## 3.3 模块边界

- `cocos/ui` 偏交互组件和布局。
- `cocos/2d/framework` 偏 UI 基础组件与渲染根。
- `cocos/2d/renderer` 负责批处理与绘制提交。

---

## 4. Physics 模块（3D + 2D）

## 4.1 3D 物理（`cocos/physics`）

- 入口：`cocos/physics/framework/index.ts`
- 核心：`PhysicsSystem`、`RigidBody`、各类 `Collider` / `Constraint`
- 后端：`builtin` / `cannon` / `bullet` / `physx`

关键点：

- `PhysicsSystem` 提供重力、步进参数、射线检测、默认材质等控制面。  
- 通过 `selector` 选择实际物理世界实现。  
- 在 `DirectorEvent.INIT` 时构建并注册系统。

## 4.2 2D 物理（`cocos/physics-2d`）

- 入口：`cocos/physics-2d/framework/index.ts`
- 核心：`PhysicsSystem2D`、`RigidBody2D`、`Collider2D`、2D joints
- 后端：`builtin` / `box2d` / `box2d-wasm` / `box2d-jsb`

关键点：

- `PhysicsSystem2D.postUpdate(deltaTime)` 每帧执行步进，并在前后触发 `BEFORE_PHYSICS/AFTER_PHYSICS`。  
- `RigidBody2D` 负责 2D 刚体参数到后端 body 的映射。

## 4.3 模块边界

- 3D 与 2D 两套系统并行、接口风格相近但实现独立。
- 业务排障先分清“2D 还是 3D”，再进入对应 backend 子目录。

---

## 5. Audio 模块

## 5.1 入口与核心对象

- 入口：`cocos/audio/index.ts`
- 核心对象：
  - `AudioClip`（资源）
  - `AudioSource`（组件，播放控制）
  - `audioManager`（全局播放管理）

## 5.2 运行时链路

1. `AudioSource.clip` 变化后触发 `_syncPlayer()`。  
2. 通过 `AudioPlayer.load(...)` 异步创建播放器。  
3. `play/pause/stop/playOneShot` 通过 `audioManager` 维护当前播放集合。  
4. 达到声道上限时，`audioManager.discardOnePlayingIfNeeded()` 执行淘汰策略。

## 5.3 模块边界

- 引擎侧控制逻辑在 `cocos/audio`。
- 平台音频能力来自 `pal/audio`（播放器与 one-shot 实现）。

---

## 6. 常见问题的首轮定位顺序（S2-T4）

1. **动画不播**：先查 `Animation` 是否拿到有效 `clip`，再查 `AnimationManager` 是否已注册并更新。  
2. **UI 不显示/错位**：先查 `Canvas` 与 `UITransform` 尺寸锚点，再查 `Batcher2D` screen 与 camera 可见层。  
3. **物理不生效**：先判定 2D/3D，再查对应 `PhysicsSystem` 的 backend 选择与 enable/step 参数。  
4. **音频不出声**：先查 `AudioClip._nativeAsset`、`AudioSource._syncPlayer()`，再查 `audioManager` 是否触发声道淘汰。
