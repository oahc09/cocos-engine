# 阶段1-命令入口清单（S1-T2）

## 一、分析范围与结论速览

- 本清单基于两个入口文件：`package.json`（根目录）与 `native/package.json`（native 子目录）。
- 结论：
  - **TS 构建入口主要集中在根目录 scripts**（`build:*` 系列）。
  - **Native 的 npm 入口仅提供清理命令**（`clear-platform`），不直接承担 C++ 编译；Native 编译主链路仍是 CMake。

## 二、命令清单表（命令 / 作用 / 涉及目录 / 常见使用场景）

| 命令 | 作用 | 涉及目录 | 常见使用场景 |
| --- | --- | --- | --- |
| `npm run postinstall`（根目录） | 安装后自动串行执行 `build:debug-infos`、`build:declaration`、`build:adapter`、`build:native-pack-tool` | `scripts/`、`scripts/native-pack-tool/` | 首次 `npm install` 后完成基础构建准备 |
| `npm run build`（根目录） | 聚合构建：执行 `build:min` + `build:declaration` | `scripts/` | 需要一键生成压缩构建与声明文件 |
| `npm run build:adapter`（根目录） | 构建平台适配层（`build-adapter.js`） | `scripts/`、`platforms/`（适配相关） | 修改平台适配逻辑后重建 |
| `npm run build:const`（根目录） | 生成/刷新编译常量（`build-const.js`） | `scripts/`、常量配置文件相关目录 | 常量或特性开关变更后刷新 |
| `npm run build:dev`（根目录） | 开发态构建：先 `build:debug-infos`，再产出 h5 source 版本 | `scripts/`、`cocos/`、`bin/` | 本地调试、排查源码行为 |
| `npm run build:debug-infos`（根目录） | 生成调试信息（供后续构建链复用） | `scripts/` | 执行 dev/min 构建前的通用前置步骤 |
| `npm run build:declaration`（根目录） | 先 `build:const` 再生成 TS 声明文件 | `scripts/`、`@types/`、声明产物目录 | API 类型变更后更新 d.ts |
| `npm run build:min`（根目录） | 发布态压缩构建：先 `build:debug-infos`，再 h5 minified | `scripts/`、`cocos/`、`bin/` | 发布前的体积优化构建 |
| `npm run build:native-pack-tool`（根目录） | 进入 `scripts/native-pack-tool` 安装依赖并构建工具 | `scripts/native-pack-tool/` | native 打包工具变更或首次安装 |
| `npm run clear`（根目录） | 清理缓存（`clear-cache.js`） | `scripts/`、缓存目录 | 构建异常、缓存污染时清理 |
| `npm run clear:platform`（根目录） | 先执行 `native/utils/clear-platform.js` 清理不需要的平台三方库，再执行 `scripts/clear-file.js` | `native/external/`、`native/utils/`、`scripts/` | 精简第三方库、切换平台构建前清理 |
| `npm run test`（根目录） | `tsc --noEmit` + `jest` | `tests/`、TS 源码目录 | 提交前快速做类型与单测门禁 |

| `npm run update:engine-version`（根目录） | 更新/同步引擎版本信息 | `scripts/`、版本信息文件 | 发布流程或版本切换时 |
| `npm run update:native-external`（根目录） | 更新 native 外部依赖 | `native/utils/`、`native/external/` | Native 三方依赖升级/同步 |
| `npm run verify:engine-version`（根目录） | 校验版本一致性 | `scripts/` | CI 或发布前一致性检查 |
| `cd native && npm run clear-platform`（native 目录） | Native 子包唯一 script：按平台清理 external 目录 | `native/utils/`、`native/external/` | 仅在 native 子目录内做平台依赖清理 |

## 三、TS 构建链路命令（最短路径）

### 1) 开发调试最短路径

1. `npm install`（根目录，自动触发 `postinstall`）  
2. `npm run build:dev`

说明：这是最短可用链路，能够得到开发态源码构建结果，适合本地调试。

### 2) 发布构建最短路径

1. `npm run build:min`

说明：在依赖已安装且前置构建信息可用时，可直接走发布压缩链路。

## 四、Native 构建链路命令（最短路径）

> 注意：`native/package.json` 不提供 C++ 编译脚本，npm 入口只负责清理平台依赖；真正编译走 CMake。

### 1) Native 侧依赖清理最短路径

1. `npm run clear:platform`（根目录）  
   或  
   `cd native && npm run clear-platform`

### 2) Native 编译最短路径（Windows 常见）

1. `cd native`  
2. `cmake -B build-win64 -A x64`  
3. `cmake --build build-win64 --config Release`

说明：上面是 CMake 的最短编译入口；Android/iOS 会在第 2 步增加 toolchain 参数。

## 五、3 个常见误用点（高频）

1. **在错误目录执行命令**：在根目录执行 `npm run clear-platform` 会失败（根目录叫 `clear:platform`）；在 `native/` 目录才是 `clear-platform`。  
2. **把 `build` 当成开发调试命令**：`npm run build` 默认走 `build:min` + 声明生成，更偏发布/产物准备，不是最轻调试链路；调试应优先 `build:dev`。  
3. **误以为 native npm 脚本可直接编译 C++**：`native/package.json` 没有 `build`；若要编译 Native，需要走 CMake（并先满足 VS/NDK/CMake 环境要求）。
