# 阶段2-渲染主线拆解（S2-T3）

> 范围：`cocos/gfx/` + `cocos/render-scene/` + `cocos/rendering/`  
> 目标：建立从设备初始化到每帧提交的渲染主链路。

---

## 1. 三层职责总览

- `cocos/gfx/`：图形设备抽象层（Device/Swapchain/Buffer/Texture/RenderPass 等）。
- `cocos/render-scene/`：渲染场景层（Camera/Light/Model 的渲染态组织与更新）。
- `cocos/rendering/`：渲染管线层（Pipeline/Flow/Stage，对 Camera 执行渲染流程）。

可以把它记为：

**设备层（能画） -> 场景层（画什么） -> 管线层（怎么画）**。

---

## 2. 启动链路（渲染初始化）

## 2.1 `Game.init()` 里的关键渲染步骤

在 `cocos/game/game.ts`：

1. `deviceManager.init(canvas, bindingMappingInfo)` 初始化 GFX 设备与 swapchain。  
2. `effectSettings.init(...)` 加载渲染配置（effect settings）。  
3. `cclegacy.rendering.init(deviceManager.gfxDevice, data)` 初始化渲染系统。  
4. `director.init()` 创建并初始化 `Root`。  

## 2.2 设备层关键入口

在 `cocos/gfx/device-manager.ts`：

- `DeviceManager.init(...)` 根据 `renderMode` 选择 WebGL/WebGPU/Headless。
- `_initSwapchain()` 创建交换链，绑定窗口尺寸。
- `deviceManager.gfxDevice` / `deviceManager.swapchain` 成为后续渲染根依赖。

---

## 3. 每帧链路（核心）

## 3.1 Director 到 Root

在 `cocos/game/director.ts`：

- `Director.tick(dt)` 中触发 `BEFORE_DRAW` 后执行 `root.frameMove(dt)`，结束后触发 `AFTER_DRAW`。

## 3.2 Root 帧处理

在 `cocos/root.ts`：`frameMove(dt)` 分为三段：

1. `_frameMoveBegin()`
   - 清理批次、重置本帧相机列表。

2. `_frameMoveProcess()`
   - 从窗口抽取渲染相机 `window.extractRenderCameras(cameraList)`。
   - `device.acquire(...)` 获取交换链。
   - 更新 2D batcher。
   - 更新各 `RenderScene`（灯光、模型、UBO 等数据）。

3. `_frameMoveEnd()`
   - 发 `Director.EVENT_BEFORE_COMMIT`。
   - 相机按 priority 排序。
   - 发 `Director.EVENT_BEFORE_RENDER`。
   - `pipeline.render(cameraList)` 执行管线渲染。
   - 发 `Director.EVENT_AFTER_RENDER`。
   - `device.present()` 提交到屏幕。

---

## 4. 管线层执行（Pipeline -> Flow -> Stage）

## 4.1 RenderPipeline

在 `cocos/rendering/render-pipeline.ts`：

- `activate(swapchain)`：初始化全局描述集、UBO、场景数据并激活所有 flow。
- `render(cameras)`：
  1) `commandBuffer.begin()`  
  2) 每个 camera 做剔除（`sceneCulling` 等）与 UBO 更新  
  3) 顺序执行 `_flows[j].render(camera)`  
  4) `commandBuffer.end()` + `device.queue.submit(...)`

## 4.2 RenderFlow

在 `cocos/rendering/render-flow.ts`：

- `activate()` 时按 stage priority 排序并激活。
- `render(camera)` 顺序执行所有启用的 stage。

## 4.3 RenderStage

在 `cocos/rendering/render-stage.ts`：

- 是实际渲染执行单元（清屏、收集、记录命令、输出 framebuffer）。
- 通过 `render(camera)` 落地单阶段绘制。

---

## 5. 场景层与相机数据流

在 `cocos/render-scene/core/render-scene.ts`：

- `RenderScene` 维护 Camera/Light/Model/2D batch。
- `update(stamp)` 每帧刷新光照与模型渲染态，供管线读取。

在 `cocos/render-scene/scene/camera.ts`：

- Camera 保存视锥、投影、viewport、clear flags 等渲染输入参数。
- Root 与 Pipeline 都以 camera 为粒度推进渲染。

---

## 6. 常见问题定位路径（S2-T3）

1. **无画面输出**：先查 `deviceManager.init` 是否成功 + `swapchain` 是否创建。  
2. **有逻辑无渲染**：查 `Director.tick` 是否到 `root.frameMove`。  
3. **有相机但不出图**：查 `cameraList` 是否为空、priority 与启用状态。  
4. **管线不工作**：查 `Root.setRenderPipeline` 是否激活成功。  
5. **提交失败或闪屏**：查 `pipeline.render` 到 `device.queue.submit/present` 链路。

## 7. 2D UI 渲染流程详解

### 7.1 核心类与职责

| 类 | 文件路径 | 职责 |
|---|---|---|
| `Batcher2D` | `cocos/2d/renderer/batcher-2d.ts` | 2D 批处理引擎，驱动遍历、合批、提交 |
| `DrawBatch2D` | `cocos/2d/renderer/draw-batch.ts` | 一次合批后的绘制指令 |
| `RenderRoot2D` | `cocos/2d/framework/render-root-2d.ts` | Canvas/Screen 根节点，注册 screen 到 Batcher2D |
| `UIRenderer` | `cocos/2d/framework/ui-renderer.ts` | 所有可渲染 UI 组件基类（Sprite/Label/Graphics 等） |
| `IAssembler` | `cocos/2d/renderer/base.ts` | 组件级顶点装配接口（不同 Sprite/Label 有不同实现） |
| `StaticVBAccessor` | `cocos/2d/renderer/static-vb-accessor.ts` | 共享顶点缓冲池与 chunk 分配 |
| `MeshBuffer` | `cocos/2d/renderer/mesh-buffer.ts` | 底层 VB/IB 数据 + IA 池 |
| `StencilManager` | `cocos/2d/renderer/stencil-manager.ts` | Mask 模板的 stencil 状态管理 |
| `UIPhase` | `cocos/rendering/ui-phase.ts` | 在 ForwardStage 末尾执行 2D 绘制 |

### 7.2 2D 帧生命周期

在 `Root.frameMove()` 中，2D 渲染穿插于三段流程：

**阶段1 — `_frameMoveBegin()`**（`cocos/root.ts`）
```
for each scene: scene.removeBatches()   // 清除上一帧的 DrawBatch2D
```

**阶段2 — `_frameMoveProcess()`**
```
batcher2D.update()        // 遍历 UI 树，收集顶点，合批
batcher2D.uploadBuffers() // 上传 VB/IB 到 GPU
for each scene: scene.update(stamp)  // 3D 模型/灯光更新
```

**阶段3 — `_frameMoveEnd()`**
```
pipeline.render(cameras)  // 3D 管线运行；UIPhase 在 ForwardStage 末尾绘制 2D
batcher2D.reset()         // 回收 DrawBatch2D，重置状态
```

### 7.3 Batcher2D.update() 详述

文件：`cocos/2d/renderer/batcher-2d.ts`

对每个注册的 screen（`RenderRoot2D`）：

1. 重置透明度追踪状态。
2. **`walk(screen.node)`** — 深度优先递归遍历 UI 树。
3. 遍历结束后 `autoMergeBatches()` 刷新最后一个累积批次。
4. 遍历 `_batches` 数组，对每个 batch：
   - model 类型的 batch：设置 subModel 的 priority。
   - mesh 类型的 batch：通过 `DescriptorSetCache` 获取/创建 DescriptorSet。
   - 调用 `scene.addBatch(batch)` 挂到 `RenderScene._batches`。

### 7.4 Batcher2D.walk(node) — UI 树遍历核心

文件：`cocos/2d/renderer/batcher-2d.ts`

1. 跳过不活跃节点。
2. 读取 `node._uiProps.uiComp` 获取 `UIRenderer`。
3. **级联透明度** = 父节点透明度 × 组件 alpha × localOpacity。
4. 若节点可见（opacity > 0）且有 `UIRenderer`：
   - 调用 `_handleUIRenderer(render, opacity, opacityDirty)`
   - 内部调用 `render.fillBuffers(this)`。
5. 递归 walk 所有子节点。
6. 子节点处理完毕后调用 `render.postUpdateAssembler(this)`（如 Mask 退出处理）。
7. 遇到 Mask 退出时，刷新批次并调用 `StencilManager.exitMask()`。

### 7.5 UI 组件数据提交：fillBuffers -> commitComp

以 **Sprite** 为例（`cocos/2d/components/sprite.ts`）：

```typescript
// Sprite._render()
render.commitComp(this, this.renderData, this._spriteFrame, this._assembler, null);
```

**`Batcher2D.commitComp()`**（合批决策点）：

1. 检查当前 renderData hash、材质、depth-stencil 状态是否变化。
2. 若状态变化 → `autoMergeBatches()` 刷新前一批次，更新 `_currRenderData`/`_currMaterial`/`_currTexture` 等。
3. 若进入 Mask stencil 层级，插入 stencil clear batch。
4. 调用 `assembler.fillBuffers(comp, batcher)` — 将索引数据写入共享 `MeshBuffer`。

**合批条件**：相同 texture hash + 相同材质 + 相同 depth-stencil 状态的组件，索引连续追加到同一 `MeshBuffer`，只在状态断开时创建新 `DrawBatch2D`。

### 7.6 autoMergeBatches() — 生成 DrawBatch2D

文件：`cocos/2d/renderer/batcher-2d.ts`

1. 从 `MeshBuffer` 获取 `InputAssembler`。
2. 设置 `ia.firstIndex = _indexStart`，`ia.indexCount = 计算索引数`。
3. 通过 `StencilManager` 解析 stencil DepthStencilState。
4. 从 `_drawBatchPool` 分配 `DrawBatch2D`，填入 texture/sampler/IA/material passes/visFlags。
5. 推入 `_batches` 数组。

### 7.7 Assembler（顶点装配器）

不同组件类型有不同 assembler（`cocos/2d/assembler/`）：

| 类型 | 路径 | 顶点数 |
|---|---|---|
| Sprite Simple | `assembler/sprite/simple.ts` | 4顶点 6索引（一个四边形） |
| Sprite Sliced | `assembler/sprite/sliced.ts` | 9宫格 36顶点 |
| Sprite Tiled | `assembler/sprite/tiled.ts` | 动态数量 |
| Sprite Bar-Filled | `assembler/sprite/bar-filled.ts` | 4-6顶点 |
| Sprite Radial-Filled | `assembler/sprite/radial-filled.ts` | 动态扇形 |
| Label TTF | `assembler/label/ttf.ts` | 按 glyph 数量 |
| Label BMFont | `assembler/label/bmfont.ts` | 按 glyph 数量 |

Simple assembler 的 `fillBuffers()` 流程：
1. 将节点的世界矩阵变换顶点位置写入 `chunk.vb`。
2. 向 `meshBuffer.iData` 追加 6 个索引（两个三角形），base vertex = chunk 的 vertexOffset。
3. `meshBuffer.indexOffset += 6`。

### 7.8 三种 2D 提交路径

| 方法 | 适用组件 | 特点 |
|---|---|---|
| `commitComp()` | Sprite, Label, RichText 等 | 世界坐标顶点，参与自动合批 |
| `commitModel()` | Graphics, UIModel | 本地坐标顶点，创建独立 Model + SubMesh，不参与自动合批 |
| `commitMiddleware()` | Spine, DragonBones | 组件自管 MeshBuffer，可选合批 |

### 7.9 顶点缓冲管理：StaticVBAccessor

- `StaticVBAccessor` 管理一组 `MeshBuffer` 实例池，使用 free-list 分配。
- 每个 `RenderData` 通过 `accessor.allocateChunk(vertexCount, indexCount)` 获取 `StaticVBChunk`。
- 多个组件共享同一 `MeshBuffer` 时，可通过同一 IA 的不同索引范围合批为一次 draw call。
- chunk 在 `RenderData` resize 或销毁时回收。

### 7.10 UIPhase — 2D 在 3D 管线中的绘制

文件：`cocos/rendering/ui-phase.ts`

`ForwardStage.render()` 末尾（以及 deferred 的 `LightingStage`）调用：

```typescript
this._uiPhase.render(camera, renderPass);
```

`UIPhase.render()` 流程：
1. 从 camera 的 renderScene 获取 `scene.batches`。
2. 对每个 batch，检查 camera visibility 与 `batch.visFlags`。
3. 对 batch 的每个 pass：
   - 通过 `PipelineStateManager` 获取/创建 PSO。
   - 绑定 pipeline state → material descriptor set → local descriptor set → input assembler。
   - `cmdBuff.draw(inputAssembler)` — 实际 GPU 绘制。

### 7.11 2D 渲染端到端流程图

```
Root.frameMove()
  |
  +-- _frameMoveBegin()
  |     +-- renderScene.removeBatches()  // 清除上帧 2D 批次
  |
  +-- _frameMoveProcess()
  |     +-- batcher2D.update()
  |     |     +-- walk(rootNode)  // 深度优先遍历 UI 树
  |     |     |     +-- 计算级联透明度
  |     |     |     +-- UIRenderer.fillBuffers(batcher)
  |     |     |     |     +-- batcher.commitComp(comp, renderData, frame, assembler)
  |     |     |     |           +-- [状态变化] autoMergeBatches() → DrawBatch2D
  |     |     |     |           +-- assembler.fillBuffers() → 写顶点/索引到 MeshBuffer
  |     |     |     +-- postUpdateAssembler()  // Mask 退出等
  |     |     +-- autoMergeBatches()  // 刷新最后一批
  |     |     +-- scene.addBatch(batch)  // 挂到 RenderScene
  |     |
  |     +-- batcher2D.uploadBuffers()  // GPU VB/IB 上传
  |
  +-- _frameMoveEnd()
        +-- pipeline.render(cameras)
        |     +-- ForwardStage.render(camera)
        |           +-- [3D 不透明/透明渲染队列]
        |           +-- UIPhase.render(camera, renderPass)  // 2D 始终在 3D 之后
        |                 +-- 遍历 scene.batches[]
        |                 +-- 绑定 PSO + DescriptorSet + IA
        |                 +-- cmdBuff.draw(ia)
        +-- batcher2D.reset()  // 回收资源
```

## 8. 3D 模型渲染流程详解

### 8.1 核心类与职责

| 类 | 文件路径 | 职责 |
|---|---|---|
| `MeshRenderer` | `cocos/3d/framework/mesh-renderer.ts` | 3D 网格渲染组件 |
| `ModelRenderer` | `cocos/misc/model-renderer.ts` | MeshRenderer 基类 |
| `Model` | `cocos/render-scene/scene/model.ts` | 渲染场景中的模型对象 |
| `SubModel` | `cocos/render-scene/scene/submodel.ts` | 子模型（一个 SubMesh + 一个 Material 的组合） |
| `SkinningModel` | `cocos/3d/models/skinning-model.ts` | 骨骼动画模型 |
| `ForwardPipeline` | `cocos/rendering/forward/forward-pipeline.ts` | 前向渲染管线 |
| `ForwardStage` | `cocos/rendering/forward/forward-stage.ts` | 前向渲染阶段 |
| `RenderQueue` | `cocos/rendering/render-queue.ts` | 渲染队列（不透明/透明排序） |
| `ShadowFlow` | `cocos/rendering/shadow/shadow-flow.ts` | 阴影渲染流 |
| `ShadowStage` | `cocos/rendering/shadow/shadow-stage.ts` | 阴影渲染阶段 |

### 8.2 3D 模型注册流程

从 `MeshRenderer` 组件到 `RenderScene`：

1. **`MeshRenderer.onLoad()`/`onEnable()`** 触发 `_updateModels()`。
2. **`_createModel()`** 调用 `Root.createModel()` 创建 `Model` 实例：
   - 普通网格 → `Model`
   - Morph 目标 → `MorphModel`
   - 骨骼动画 → `SkinningModel`（宏 `CC_USE_SKINNING=true`）
3. **`_attachToScene()`** 调用 `renderScene.addModel(this._model)` 注册到渲染场景。
4. **`_updateModelParams()`** 遍历所有 `RenderingSubMesh`，对每个子网格：
   - 调用 `model.initSubModel(i, subMeshData, material)`。
5. **`Model.initSubModel()`**（`model.ts`）：
   - 创建 `SubModel`，调用 `subModel.initialize(subMesh, mat.passes, macroPatches)`。
   - `SubModel.initialize()` 创建 GFX `InputAssembler` 和 `DescriptorSet`。
   - `_flushPassInfo()` 通过 `pass.getShaderVariant(patches)` 编译每个 pass 的 Shader。

**SubModel 结构**：每个 SubModel 持有 `_passes`、`_shaders`、`_subMesh`、`_inputAssembler`、`_descriptorSet`，存在 1:1:1 的关系（sub-mesh : material : SubModel）。

### 8.3 每帧模型更新

`RenderScene.update(stamp)` 每帧执行：
- 遍历所有 models → `model.updateTransform(stamp)` 更新世界矩阵。
- `model.updateUBOs(stamp)` 将世界矩阵和逆转置写入本地 UBO 缓冲并上传 GPU。

### 8.4 ForwardPipeline 架构

```
ForwardPipeline
  +-- ShadowFlow (priority: SHADOW)
  |     +-- ShadowStage
  +-- ReflectionProbeFlow
  |     +-- ReflectionProbeStage
  +-- ForwardFlow (priority: FORWARD)
        +-- ForwardStage
              +-- RenderQueue[0]: 不透明（FRONT_TO_BACK）
              +-- RenderQueue[1]: 透明（BACK_TO_FRONT）
              +-- RenderInstancedQueue（实例化批次）
              +-- RenderAdditiveLightQueue（逐光源 additive pass）
              +-- PlanarShadowQueue
              +-- UIPhase
```

### 8.5 每帧渲染流程

**`RenderPipeline.render(cameras)`**（`render-pipeline.ts`）对每个 camera：

```
1. validPunctualLightsCulling()  // 灯光剔除
2. sceneCulling()                // 模型视锥剔除 → renderObjects[]
3. pipelineUBO.updateGlobalUBO()
4. pipelineUBO.updateCameraUBO()
5. for each flow: flow.render(camera)
```

### 8.6 sceneCulling — 视锥剔除

文件：`cocos/rendering/scene-culling.ts`

1. 清空 `pipelineSceneData.renderObjects`。
2. 若启用阴影，更新 CSM 层级。
3. 遍历 `scene.models`：
   - 检查 `model.enabled`、`camera.visibility` 可见性、LOD 级别。
   - **视锥剔除**：`intersect.aabbFrustum(model.worldBounds, camera.frustum)`。
   - 通过剔除的模型推入 `renderObjects[]`（`{ model, depth }`）。
   - 阴影投射体推入 `castShadowObjects[]` 和 `csmLayerObjects[]`。

### 8.7 ForwardStage.render(camera) — 核心绘制

文件：`cocos/rendering/forward/forward-stage.ts`

1. 清空渲染队列和实例化队列。
2. 遍历 `pipelineSceneData.renderObjects`：
   - 对每个 render object，遍历其 `subModels`，再遍历每个 subModel 的 `passes`。
   - 按 `pass.phase` 过滤（default 阶段）。
   - 若 `pass.batchingScheme === INSTANCING` → 合入 `InstancedBuffer`。
   - 否则 → `insertRenderPass()` 插入对应 `RenderQueue`。
3. 排序队列（不透明：从前到后按 priority/depth/shaderId；透明：从后到前）。
4. 更新阴影 UBO，上传实例化缓冲。
5. **开始 RenderPass**，绑定 GLOBAL descriptor set。
6. 按顺序录制命令：
   - `renderQueues[0].recordCommandBuffer()` — 不透明物体
   - Additive instance queues
   - `instancedQueue.recordCommandBuffer()` — 实例化不透明
   - `additiveLightQueue.recordCommandBuffer()` — 逐光源 additive
   - `planarQueue.recordCommandBuffer()` — 平面阴影
   - `renderQueues[1].recordCommandBuffer()` — 透明物体
   - `UIPhase.render()` — 2D UI
   - Geometry renderer / Profiler
7. **结束 RenderPass**。

### 8.8 RenderQueue — 实际 Draw Call

文件：`cocos/rendering/render-queue.ts`

```typescript
for each renderPass in queue:
    pso = PipelineStateManager.getOrCreatePipelineState(device, pass, shader, renderPass, IA)
    cmdBuff.bindPipelineState(pso)
    cmdBuff.bindDescriptorSet(SetIndex.MATERIAL, pass.descriptorSet)  // 材质
    cmdBuff.bindDescriptorSet(SetIndex.LOCAL, subModel.descriptorSet) // 每模型数据
    cmdBuff.bindInputAssembler(IA)
    cmdBuff.draw(IA)
```

### 8.9 三级 DescriptorSet 绑定

| Set Index | 作用域 | 绑定时机 | 内容 |
|---|---|---|---|
| GLOBAL (0) | 整帧 | renderPass 开始时 | 全局 UBO、相机数据、阴影数据、shadow map 纹理 |
| MATERIAL (1) | 每个材质 pass | 每次 draw 前 | 材质 uniform、纹理 |
| LOCAL (2) | 每个 SubModel | 每次 draw 前 | 世界矩阵、逆转置、lightmap UV、反射探针数据、SH 系数、光源偏移 |

### 8.10 Shader 宏与 Pass 编译

**`SubModel._flushPassInfo()`**：对每个 pass 调用 `pass.getShaderVariant(patches)` 解析宏并返回编译后的 Shader。

**`Model.getMacroPatches()`** 收集的宏：
- `CC_RECEIVE_SHADOW` — 接收阴影
- `CC_USE_LIGHTMAP` — 使用光照贴图
- `CC_USE_LIGHT_PROBE` — 使用光照探针
- `CC_USE_REFLECTION_PROBE` — 反射探针类型
- `CC_DISABLE_DIRECTIONAL_LIGHT` — 禁用方向光
- `CC_USE_SKINNING` — 骨骼动画（SkinningModel）

### 8.11 阴影系统

**两种阴影类型**：

**ShadowMap（`ShadowType.ShadowMap`）**：
- 由 `ShadowFlow` → `ShadowStage` 执行。
- 主方向光：创建/更新 shadow framebuffer，对每个 CSM 级别（1-4 级）渲染。
- Spot light：类似，创建 framebuffer 渲染。
- `ShadowStage.render()`：更新阴影 UBO → 收集 shadow casters → 在 shadow framebuffer 上录制绘制命令。

**Planar Shadow（`ShadowType.Planar`）**：
- 在 `ForwardStage` 内部执行。
- `PlanarShadowQueue.gatherShadowPasses()`：遍历场景模型，按 castShadow + visibility 过滤，用 `shadows.matLight` 变换包围盒做视锥测试。
- 支持实例化合并。

### 8.12 实例化渲染

当 `pass.batchingScheme === INSTANCING` 时：

1. `InstancedBuffer.merge(subModel, passIdx)` 将每实例顶点属性（世界矩阵行、SH 数据等）合入共享顶点缓冲。
2. `RenderInstancedQueue.recordCommandBuffer()` 绑定材质 descriptor set 一次，遍历实例仅绑定 LOCAL descriptor set（使用 dynamic offset）。

### 8.13 RenderScene 管理的渲染对象

| 集合 | 类型 | 添加/移除方法 |
|---|---|---|
| `_models` | `Model[]` | `addModel()` / `removeModel()` |
| `_cameras` | `Camera[]` | `addCamera()` / `removeCamera()` |
| `_mainLight` | `DirectionalLight` | `setMainLight()` |
| `_sphereLights` | `SphereLight[]` | `addSphereLight()` / `removeSphereLight()` |
| `_spotLights` | `SpotLight[]` | `addSpotLight()` / `removeSpotLight()` |
| `_pointLights` | `PointLight[]` | `addPointLight()` / `removePointLight()` |

### 8.14 3D 渲染端到端流程图

```
MeshRenderer.onEnable()
  → _createModel() → Root.createModel()
  → _attachToScene() → RenderScene.addModel(model)
  → _updateModelParams() → model.initSubModel() → SubModel(IA + DescriptorSet + Shader)

每帧渲染:
  Root.frameMove()
    → RenderScene.update() → 更新所有模型 transform + UBO
    → RenderPipeline.render(cameras)
        for each camera:
          → sceneCulling() → 视锥剔除 → renderObjects[]
          → ForwardFlow.render(camera)
              → ForwardStage.render(camera)
                  → 遍历 renderObjects → 分配到 RenderQueue / InstancedQueue
                  → 排序队列
                  → BeginRenderPass + 绑定 GLOBAL descriptor set
                  → 不透明队列 recordCommandBuffer()
                      → bindPSO + bindMaterialSet + bindLocalSet + draw(IA)
                  → 实例化队列 recordCommandBuffer()
                  → AdditiveLight 队列
                  → 平面阴影
                  → 透明队列 recordCommandBuffer()
                  → UIPhase.render() — 2D UI
                  → EndRenderPass
    → Device.queue.submit(commandBuffers)
```

### 8.15 2D 与 3D 渲染的关系

2D 和 3D **不是**在 Flow 层面分离，而是共用 `ForwardFlow`。分离发生在 **数据收集** 和 **绘制提交** 层面：

- **3D 物体**：通过 `RenderScene._models` → `sceneCulling()` → `pipelineSceneData.renderObjects` → `RenderQueue.recordCommandBuffer()`。
- **2D 物体**：通过 `RenderScene._batches`（`Batcher2D.update()` 填充）→ `UIPhase.render()`。

2D UI 始终在 3D 内容之后绘制（同一 render pass 内），保证 UI 叠加在 3D 场景之上。

## 9. 常见问题定位路径（补充）

### 2D 相关

1. **UI 不显示**：查 `RenderRoot2D` 是否注册到 `Batcher2D`，`walk()` 是否遍历到该节点。
2. **合批未生效**：查相邻组件是否共享相同 texture/material/depth-stencil 状态。
3. **Mask 裁剪异常**：查 `StencilManager` 层级栈是否正确 push/pop。
4. **UI 闪烁/错乱**：查 `uploadBuffers()` 是否在 `pipeline.render()` 之前完成。

### 3D 相关

5. **模型不显示**：查 `MeshRenderer._attachToScene()` 是否调用，`RenderScene._models` 中是否有该 model。
6. **模型在视锥内但不渲染**：查 `camera.visibility` 与 `model.visibility` 是否匹配。
7. **阴影缺失**：查 `ShadowFlow` 是否激活，模型是否设为 `castShadow`。
8. **材质错误**：查 `SubModel._flushPassInfo()` 中的 shader 宏 patches 是否正确。
9. **实例化不生效**：查 pass 的 `batchingScheme` 是否为 `INSTANCING`。
