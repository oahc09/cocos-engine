# 阶段1-配置项对照表（S1-T3）

## 一、配置定位（重点）

- `tsconfig.json`：约束 TypeScript 编译行为、类型检查强度与类型可见性，是**开发期与编译期质量门禁**。
- `cc.config.json`：定义引擎 feature 组合、平台条件替换、构建常量和裁剪策略，是**构建产物形态与运行时行为开关**。

## 二、关键配置对照表

| 配置项 | 位置 | 作用 | 影响范围 | 修改风险 |
| --- | --- | --- | --- | --- |
| `compilerOptions.strict` | `tsconfig.json > compilerOptions.strict` | 开启严格类型检查 | 全量 TS 源码的类型错误暴露与代码规范 | 高 |
| `compilerOptions.target` | `tsconfig.json > compilerOptions.target` | 指定 JS 语法目标（当前 `es6`） | 输出语法兼容性、运行环境要求 | 中 |
| `compilerOptions.module` | `tsconfig.json > compilerOptions.module` | 指定模块系统（当前 `commonjs`） | 模块解析、打包工具兼容性 | 中 |
| `compilerOptions.noEmit` | `tsconfig.json > compilerOptions.noEmit` | 只做类型检查，不输出编译产物 | 本地构建链路与调试流程 | 中 |
| `compilerOptions.paths` + `baseUrl` | `tsconfig.json > compilerOptions.paths/baseUrl` | 配置路径别名（如 `cc.decorator`） | import 解析、IDE 跳转、编译解析一致性 | 高 |
| `compilerOptions.types` | `tsconfig.json > compilerOptions.types` | 显式注入全局/平台/外部类型声明 | 全局类型污染、重名冲突、平台 API 类型可见性 | 高 |
| `include` | `tsconfig.json > include` | 限定参与检查的源码范围 | 类型检查覆盖面与漏检风险 | 中 |
| `features.<id>.modules` | `cc.config.json > features.*.modules` | 定义启用 feature 时纳入的公共模块 | 引擎 API 暴露面、功能可用性、包体积 | 高 |
| `features.<id>.dependentModules` | `cc.config.json > features.*.dependentModules` | 声明 feature 的模块依赖 | 运行时完整性（避免缺模块） | 中 |
| `features.<id>.overrideConstants` / `intrinsicFlags` | `cc.config.json > features.*.overrideConstants/intrinsicFlags` | feature 启用时覆盖编译常量 | 条件编译分支、平台行为差异 | 高 |
| `moduleOverrides[].test` + `moduleOverrides[].overrides` | `cc.config.json > moduleOverrides[]` | 按构建条件映射/替换模块实现 | 多平台实现路由、JSB/NATIVE 分支正确性 | 高 |
| `constants.<name>.value` / `dynamic` / `internal` | `cc.config.json > constants.*` | 定义编译期常量值、动态性、对外可见性 | 条件裁剪、运行时判断、对外 API 常量暴露 | 高 |
| `treeShake.noSideEffectFiles` | `cc.config.json > treeShake.noSideEffectFiles` | 标记无副作用文件用于裁剪优化 | 打包体积与潜在误删副作用代码风险 | 高 |
| `optimizeDecorators.fieldDecorators/editorDecorators` | `cc.config.json > optimizeDecorators.*` | 声明可优化/可移除装饰器集合 | 序列化、编辑器元信息、构建优化效果 | 中高 |
| `includes` | `cc.config.json > includes` | quick-compiler 的源码纳入范围 | 编译覆盖面、模块可解析性 | 高 |

## 三、修改前检查清单（执行版）

1. 先确认目标：本次修改是为**类型约束、功能裁剪、平台适配**中的哪一类。
2. 若改 `features.*.modules`，同步核对 `dependentModules` 是否完整。
3. 若改 `moduleOverrides`，逐条确认 `test` 条件互斥/覆盖关系，避免错误命中。
4. 若改 `moduleOverrides.overrides`，确认源路径与目标路径都存在且导出接口兼容。
5. 若改 `constants`，核对是否影响 `NATIVE/HTML5/MINIGAME` 等关键分支。
6. 若改 `treeShake.noSideEffectFiles`，先确认文件确实无副作用（无全局注册/初始化逻辑）。
7. 若改 `optimizeDecorators`，确认不会破坏编辑器属性面板、序列化与运行时反射。
8. 若改 `tsconfig.paths/types/include`，先做一次全量类型检查，确认无新冲突。
9. 若改 `strict/noImplicitAny` 等强约束项，预估修复成本并分批推进。
10. 修改后至少验证一次 Web 与 Native（或最小双平台）构建与启动链路。
